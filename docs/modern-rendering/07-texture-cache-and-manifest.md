# Phase 07 — Background texture cache and the generated-asset manifest

**One session, one commit.** Depends on: 01. Player sees: faster loads after the first few
sessions, less VRAM, and a settings panel that says "not generated yet — 63 %" instead of
silently doing nothing. Nothing to download.

## Ships

- **M1** — a background worker that BC7-encodes (BC5 for normals; ASTC 6×6 on Android)
  every texture the client had to hold uncompressed — PNG overrides
  (`asset_manager.cpp:431`), uncompressed BLPs, phase-01 normal maps — and stores KTX2
  with mips under `Data/generated/<expansion>/textures/<hash>.ktx2`. Loader prefers the
  cached file. Runs on loading screens and idle frames (`thread_pool`), bounded by a
  per-frame budget so it never costs a frame.
- The **manifest** `Data/generated/<expansion>/generated.json` (plan §4.11) written
  incrementally; `source_manifest_hash` staleness; per-entry `src_hash`.
- **`requires`** on `SettingDesc` + the `unavailable` fill from the manifest ("Not
  generated", "N % done", "Generated by an older tool").
- `tools/generate_assets` CLI: the same worker run to completion from the command line
  (pre-warm), `--expansion`, `--target`, budget print. Enumerates through `manifest.json`.
- Phase-01's normal cache directory is adopted into the manifest.

## Not in this session

- Roughness/AO class generator → 12. Splat height → 17. AI pack reader → 24.

## Steps

1. Encoder: vendor `bc7enc_rdo` (MIT, single file) and `astcenc` as a subprocess on Android
   builds; `include/pipeline/texture_cache.hpp`.
2. `AssetManager::loadTexture` (`asset_manager.cpp:325`): after resolving a source, hash
   its bytes (xxh3), look up the cache; hit → KTX2 upload path in `vk_texture.cpp` (add
   BC7 / BC5 / ASTC formats beside `vk_texture.cpp:278`); miss → today's path plus a queued
   encode job.
3. Manifest writer/reader (`pipeline/generated_manifest.{hpp,cpp}`), fsync'd every 100
   entries and on shutdown; on start compare `source_manifest_hash`.
4. Schema: `requires` field; `Application` fills the overlay after the manifest loads
   (the phase-01 mechanism). First consumer: a `texturecache` row (below).
5. CLI target `generate_assets` in `CMakeLists.txt` linking `src/pipeline/`; CI runs it on
   200-file samples of the four extractions the way `docs/plan-modern-rendering.md` §4.11
   item 6 describes — the sample extractions must be added to the CI fixtures this session
   (small, hashed, no Blizzard bytes committed: generated from the harness's own test
   textures under `tests/`).
6. Settings.

## Verify

- Cold start Stormwind: load time within 10 % of phase 06; after three loading screens the
  cache is > 90 % complete for Stormwind's set (log line); warm start ≥ 20 % faster than
  phase 06 with a PNG-override pack installed, and VRAM down by the RGBA8→BC7 ratio.
- Switch expansion roots: panel shows "stale" reasons, nothing crashes, regeneration resumes.
- `generate_assets --expansion wotlk` on the T0 machine: completes, manifest `complete: true`.
- Compare mode all scenes: bit-identical to phase 06 (BC7 at RDO 0 is visually lossless on
  these sources; assert SSIM ≥ 0.995, and inspect the diff on `character-portrait`).

## Commit

```
Compress textures in the background and keep a manifest of what was made

A worker encodes every texture the client held uncompressed to BC7 or
ASTC on loading screens and idle frames, under a per-expansion
manifest that records source hashes and completeness. Settings that
need generated data say how far along it is instead of doing nothing.
generate_assets runs the same worker from the shell for anyone who
wants it done at once.
```
